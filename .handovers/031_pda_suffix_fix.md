# 031 — PDA Derivation Fix: Missing `ProgramDerivedAddress` Suffix

## What Happened

Continued devnet E2E validation for Issue #010 Phase 4. After the previous session's `curve25519-dalek` fix (commit `44025d9`), PDA derivation was validated against the actual Solana blockchain. A **critical bug** was discovered: `find_program_address` was missing the required `"ProgramDerivedAddress"` suffix in the SHA-256 hash input, causing **every PDA ever derived by the worker to be completely wrong**.

## Branch

- `feature/010_deposit_refund_escrow` on `event-checkin/`

## Changes Summary

### The Bug: Missing `ProgramDerivedAddress` Suffix

Solana's `find_program_address` computes:
```
SHA-256(seeds + bump + program_id + "ProgramDerivedAddress")
```

Our worker was computing:
```
SHA-256(seeds + bump + program_id)   // ← missing 21-byte suffix
```

This suffix is documented in the [Solana SDK source](https://github.com/solana-labs/solana/blob/master/sdk/src/pubkey.rs#L142) and in `@solana/web3.js` `createProgramAddressSync`.

### How It Was Found

1. All 36 unit tests passed — because test vectors were generated by the same buggy implementation (circular verification)
2. Worker started locally, deposit endpoints exercised against devnet
3. Cross-check against `@solana/web3.js` `findProgramAddressSync` (v1.95.8) revealed all 4 PDAs were different
4. Reading web3.js source revealed the `"ProgramDerivedAddress"` suffix

### Two Separate Bugs (Root Cause)

1. **Bug #1 (fixed in `44025d9`)**: `is_on_ed25519_curve` broken — hand-rolled field arithmetic returned wrong results. Fixed by using `curve25519-dalek`.
2. **Bug #2 (fixed in `42a1bd7`)**: `find_program_address` missing `"ProgramDerivedAddress"` suffix — produces wrong address regardless of correct bump.

Both went undetected because test vectors were self-referential (generated by the same buggy code they tested against).
